# Platform qualification

No Lora Agent binary or tested hardware combination is claimed by this package. Qualify complete combinations of host OS/build, architecture, worker digest, model digest, filesystem, driver and operation. A portable crate or a backend listed by upstream is a candidate for testing. A Linux x86-64 CPU reference rig provides the first reproducible baseline. Windows x86-64 and macOS arm64 are additional primary CPU candidates.

## Promotion evidence

1. Build the exact pinned CPU worker and host from a clean checkout. Record compiler, target triple, baseline ISA and dynamic dependencies. Have an independent machine install the resulting artifact offline.
2. Run golden model import, hostile artifact rejection, worker negotiation, first token, scoped read, cancellation, insufficient-memory handling, kill/restart and uninstall under an ordinary account. Cross-compilation covers buildability only.
3. Validate OS containment and filesystem race fixtures on the actual advertised filesystem. If unavailable, expose a capability-unavailable result and qualify only the narrower mode. Explicitly list degraded sensors, missing VRAM budgets and unsupported tool modes.
4. For each GPU path, test a pinned driver/runtime/device family, reported memory vs peak, offload and conservative CPU fallback without a data leak. A missing runtime library must not prevent CPU startup. Hardware measurements are attached to a named combination.
5. Publish revisioned evidence with artifact digests, host details, fixture outcomes, known limitations and release date. On a dependency, driver or OS change, rerun impacted gates. Downgrade support after an unresolved regression. GPU success cannot imply training, multi-GPU, privileged or desktop qualification.

Where vendor sensor APIs, browser automation or desktop portals are absent, display a precise missing capability. Standard users can use qualified local chat independently of those features.
