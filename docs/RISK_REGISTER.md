# Risk register

Design-stage assessments dated 2026-11-04. Likelihood applies during development and qualification. Severity is the consequence if an affected build ships. Critical means disclosure, unauthorized effects or compromise of the host. High means loss of data, repeatable crashes, a failed qualification target or materially wrong results. Medium means degraded function or costly rework. Ratings are engineering judgments, not observed failure rates.

## Highest priority unknowns

Before expanding the MVP, establish that a small qualified model reliably issues a useful file-read proposal, memory estimates leave enough headroom during load and prefill, child confinement actually holds on each advertised OS, and a native-code crash leaves a recoverable run. Before training is promoted, prove that the adapter can run on the intended inference backend and improves a held-out task. The [benchmark plan](BENCHMARK_PLAN.md) defines the controlled comparisons.

| ID · owner | Failure and early signal | Severity / likelihood | Mitigation and qualification evidence | Fallback |
| --- | --- | --- | --- | --- |
| R01 · runtime | Driver or ISA mismatch causes an illegal instruction, startup failure or hang despite a detected device | High / high | Probe using the exact worker binary. Record OS/arch/ISA/backend/driver tuple and test on physical machines. Quarantine failing builds by fingerprint. | Select qualified CPU baseline with user-visible reason, or reject unsupported host. |
| R02 · scheduler | Weights fit on disk but KV, scratch or transient copies exceed available memory; unified memory counted twice | High / high | Separate pools and reservation accounting, measure load/prefill peaks, stress competing processes and missing sensors. | Deny admission and offer shorter context, alternate quant or smaller model. |
| R03 · inference | Model schema, tokenizer, prompt template or upstream C API changes silently alter output | High / high | Pin engine, template, tokenizer, model digest and build flags. Check token IDs, structured output and cancellation on each upgrade. | Keep previous verified pair; expose chat-only if tool contract fails. |
| R04 · security | Untrusted GGUF metadata or native memory error escapes parser or reads unrelated files | Critical / medium | Size and offset limits, audited FFI ownership, fuzz malformed inputs, sanitizer builds and denied network/unauthorized file probes on each worker sandbox. | Accept only qualified digests on a restricted build or disable the affected target. |
| R05 · tools | Symlink, junction, mount, hardlink alias or file replacement defeats the authorized read | Critical / medium | Anchor beneath an opened directory, verify type and resource identity at use, disallow unsupported link cases, race in native tests, enforce byte budgets. | Require trusted user-selected exact file handle or disable file tool on that OS. |
| R06 · agent | Prompt injection or weak model emits forged grants, loops or claims an unsupported result | Critical / high | Closed schemas, authenticated human approval and independent executor, evidence references, loop caps and adversarial task corpus. | Deny invocation, return partial evidence or abstain; restrict model to chat. |
| R07 · integrations | Malicious extension, MCP server, acquired binary or dependency steals data under the user's identity | Critical / medium | Treat native processes as code with OS rights. Pin digest, verify origin, scope OS access and host calls, review upgrades, test disable and revocation. | Disable or quarantine extension, rotate exposed credentials, retain built-in tools. |
| R08 · API | Cross-origin webpage, remote client or confused deputy reaches local agent or reuses a token | Critical / medium | No MVP listener. Future bearer auth, strict Host/Origin and per-run ownership, bounded requests, explicit TLS/auth for remote binding and hostile-browser tests. | Disable listener, rotate credentials, keep in-process CLI. |
| R09 · platform | User grants OS-level accessibility or service rights broader than the intended action | Critical / medium | Separate typed broker, authenticated callers and operation-specific native approval. Test denials under standard-user profiles. | Keep privileged operations unavailable; show manual OS steps. |
| R10 · registry | Interrupted import, invalid resume response, live deletion or migration leaves dangling metadata or lost data | High / medium | Same-volume staging, immutable digests, ordered file/DB commits, leases, startup reconciliation, backup and restore tests at each boundary. | Recover previous manifest/schema from verified backup; quarantine partial data. |
| R11 · training | Dataset leakage, wrong base, unexpectedly large activation memory or incompatible adapter export | High / high | Pin data split and base digest, record peak training memory, compare held-out quality and validate export→load→inference on target. | Keep experimental adapter separate and use original base; offer offline export only when provenance is clear. |
| R12 · desktop | Long transcripts, system webview differences or inaccessible approval UI make stop/consent unusable | High / medium | Virtualize streams, coalesce updates and test keyboard, screen reader and low-end idle/peak load with real packaged app. | Ship CLI on affected target, disable expensive panels. |
| R13 · releases | Driver runtimes, native compilers, signing keys or updater break install or update | High / high | Start with one qualified package, pin sources and CI actions, verify checksums/signatures, run clean-machine install, downgrade and recovery drills. | Hold affected package; publish last verified build and restore instructions. |
| R14 · maintainers | Engine licenses, weight licenses, artwork or vendor libraries lack redistribution permission | High / medium | Track source, exact revision, SPDX expression, license text, notices and permitted uses per artifact. Review before bundling or training. | Distribute only reviewed components; allow user-supplied weights under applicable terms. |
| R15 · product | Too many backend/OS/plugin combinations exceed maintenance capacity | High / high | Require a named maintainer, hardware access, conformance tests and user workload for each addition. Track test cost and failing configurations. | Reduce the advertised matrix; defer later modules. |
| R16 · performance | Auto-tuning consumes more energy or time than the gain, or silently reduces context/quality | Medium / medium | Compare to static profiles on held-out machines. Include tuning cost, quality and temperature; invalidate cached receipts on driver/build change. | Keep conservative defaults and explicit manual overrides. |
| R17 · storage / privacy | Prompts, indexed secrets, paths or credentials persist in logs, caches or exported diagnostics | Critical / medium | Separate content from audit, purpose and workspace scopes, preview diagnostic export, purge indexes and test retention/revocation with planted secrets. | Disable affected capture or indexing, invalidate stored references, notify user of backup retention. |
| R18 · supervisor | Cancel races with exit, child survives parent or worker blocks behind a full stream queue | High / medium | Bounded buffers, independent control servicing, terminal-state compare-and-set, process-tree tests and reap-before-reuse. | Terminate job and mark interrupted; block new admission while resource release is uncertain. |

## Reopen a decision

Attach the smallest reproducing fixture, qualified tuple, raw measurements and violated acceptance case to an issue. Assign it to the subsystem owner above. A changed threat boundary, new redistribution condition or regression on a previously qualified target requires a new decision or explicit withdrawal of support before release. Record private vulnerability details through the [security policy](../SECURITY.md).
